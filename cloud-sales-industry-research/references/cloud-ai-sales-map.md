# 云 / AI 销售机会分析方法

## 1. 先画“技术资源消耗地图”

从业务链反推：
业务动作 → 技术动作 → 资源需求 → 采购品类。

示例：
用户增长
→ 请求量上升
→ 推理 QPS 上升
→ LLM API / GPU / 网络需求上升
→ 模型 API 或算力采购机会。

## 2. 机会矩阵

每个机会至少打四个分：
- 需求强度；
- 用户预算；
- 百度/目标云厂商可赢性；
- 采购紧迫度。

## 3. 按客户阶段判断

### 0→1 / Seed
典型诉求：
- 快速上线；
- credits；
- API；
- 轻架构；
- 技术支持。

### PMF / A轮
典型诉求：
- 成本优化；
- 稳定性；
- 数据；
- 监控；
- 模型路由；
- 存储和数据库。

### Scale / B轮+
典型诉求：
- 整体架构；
- 全球化；
- 安全；
- SLA；
- 大规模采购商务；
- 自研模型 / GPU；
- 多云与容灾。

### 成熟企业
典型诉求：
- 合规；
- 迁移；
- TCO；
- 集成；
- 组织治理；
- 多云；
- 长期战略合作。

## 4. 高质量销售切入，不从“产品”开始

弱：
> 我们有 GPU、模型、数据库。

强：
> 你们业务规模扩大后，哪个成本项会最快侵蚀毛利？如果是模型调用/数据采集/跨境网络，我们可以围绕 Cost-to-Serve 做架构优化。

## 5. 采购触发事件

主动寻找：
- 新融资；
- 大客户签约；
- 新产品上线；
- 用户量暴涨；
- 海外扩张；
- 模型切换；
- 自研模型；
- 成本过高；
- 稳定性事故；
- 合规要求；
- 组织新增 Infra / Data / AI 负责人；
- 大规模招聘；
- 新机房 / 新地域。
