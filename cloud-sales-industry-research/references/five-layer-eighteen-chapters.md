# 五层十八章研究框架

## Layer 1｜行业认知

### 1. Executive Summary / 执行摘要
回答：
- 行业现在处于什么阶段？
- 最重要的 5–8 个结论是什么？
- 哪些结论对技术、商业和销售最重要？
- 哪些是已验证事实，哪些仍是推断？

### 2. 一句话定义、核心概念与行业边界
回答：
- 这个行业替谁解决什么问题？
- 哪些概念容易混淆？
- 与相邻行业、上一代解决方案有什么区别？
- 哪些环节属于本行业，哪些不属于？

### 3. 第一性原理：行业为什么存在
从以下链条拆解：
需求变化 → 原有方案失效/不足 → 技术或成本条件成熟 → 新供给出现 → 付费意愿形成。

必须回答：
- 用户真正的痛点是什么？
- 为什么以前没有形成这个行业？
- 为什么是现在？
- 如果不采用这个新方案，客户会怎么解决？

### 4. 行业发展史、关键拐点与当前阶段
梳理：
- 早期形态；
- 上一代解决方案；
- 技术/政策/成本拐点；
- 代表性公司和事件；
- 当前是萌芽、早期增长、快速渗透、成熟还是出清阶段。

---

## Layer 2｜产业结构

### 5. 业务价值链
画清：
上游 → 核心平台/产品 → 下游客户 → 最终用户。

回答：
- 每一层创造什么价值？
- 谁依赖谁？
- 哪个环节最难替代？

### 6. 资金流、数据流、技术流
分别画三张图：

**资金流**
谁出钱 → 预算归属 → 谁收钱 → 钱再流向哪些供应商。

**数据流**
数据从哪里产生 → 如何采集 → 清洗/加工 → 模型/系统使用 → 如何反馈。

**技术流**
计算 → 存储 → 网络 → 数据 → 模型 → Agent/应用 → 分析/运营。

### 7. 客户类型、ICP 与主要应用场景
回答：
- 哪些行业最需要？
- 理想客户画像是什么？
- 用户需求有多高频？
- 单客户价值高不高？
- 哪些场景属于刚需，哪些只是锦上添花？

### 8. 主要玩家与战略分组
不能只列公司。
按战略组分类，例如：
- 技术平台型；
- 数据型；
- SaaS 型；
- 服务/Agency 型；
- 大平台延伸型；
- 垂直场景型。

比较：
- 产品；
- 客户；
- 技术；
- 数据；
- 渠道；
- 商业模式；
- 融资；
- 差异化；
- 风险。

### 9. 核心成功因子 KSF 与竞争壁垒
给关键能力排序。
常见候选：
- 数据；
- 算法/模型；
- 产品；
- 渠道/分发；
- 客户关系；
- 成本；
- 品牌；
- 网络效应；
- 生态；
- 合规。

明确：
什么能力只是门槛，什么能力才可能形成护城河。

### 10. 利润池
按产业链分析：
- 收入规模；
- 毛利水平；
- 议价权；
- 壁垒；
- 资本密度；
- 竞争强度；
- 利润未来向哪里迁移。

必须区分“价值大”和“利润高”。

## Layer 3｜商业模式

### 11. 收入模式与收入构成
拆出：
- 订阅；
- API；
- 项目/实施；
- 数据；
- 服务；
- 佣金；
- 广告；
- 交易抽成；
- 硬件；
- 其他。

如果可以，给收入公式：
收入 = 客户数 × ARPU + 增值收入。

### 12. 成本结构
至少分析：
- 算力；
- 模型/API；
- 数据；
- 网络；
- 存储；
- 人力；
- 销售；
- 渠道；
- 合规；
- 第三方服务。

指出：
哪些成本随业务规模线性增长，哪些具有规模效应。

### 13. Unit Economics / 单位经济模型
根据行业可得数据分析：
- 毛利；
- CAC；
- LTV；
- NRR / 留存；
- 回本周期；
- 单客户直接服务成本；
- 边际成本；
- 规模效应。

没有可靠行业数据时，建立“示意模型”，必须明确标注假设，不能伪装成真实行业均值。

### 14. 真实商业化验证、市场规模与证据质量
优先寻找：
- 真实客户；
- 真实合同；
- ARR / 收入；
- 客户数；
- 客户续费；
- 生产部署；
- 上市公司财报；
- 融资；
- 明确产品价格。

市场规模必须说明：
- 定义口径；
- 数据来源；
- 是否可追溯；
- 不同机构口径差异。

## Layer 4｜技术与趋势

### 15. 技术实现原理、关键技术链路与行业技术栈
目标：
让非技术背景用户达到“能与 CTO 交流”的程度。

输出：
- 一张完整技术链路；
- 每一环做什么；
- 输入/输出是什么；
- 技术难点；
- 成本点；
- 关键指标；
- 常见技术方案；
- 云/AI 资源使用位置。

技术解释优先中文，常见缩写可保留。

### 16. 核心变量、趋势与三情景推演
固定检查五类变量：
1. 技术；
2. 成本；
3. 供给；
4. 需求；
5. 政策/制度/平台规则。

做三情景：
- Bull：什么条件成立时行业加速？
- Base：最可能发生什么？
- Bear：什么条件会让行业受阻或失败？

每个情景必须写：
- 假设；
- 机制；
- 结果；
- 触发/验证信号。

---

## Layer 5｜销售转化

### 17. 采购决策中心、高管 KPI、典型痛点与采购触发
拆角色：
- User；
- Decision Maker；
- Economic Buyer；
- Influencer；
- Blocker。

至少覆盖：
- CEO / Founder；
- CTO / 技术负责人；
- 业务负责人；
- Infra / 算法 / 数据；
- 采购 / CFO（如相关）。

每个角色写：
- 目标；
- KPI；
- 痛点；
- 风险；
- 采购触发条件。

### 18. 云计算 / AI 销售机会地图
必须评估：
- GPU / CPU；
- 模型 API；
- 搜索；
- 数据采集；
- 对象存储；
- 数据湖/数仓；
- 数据库；
- 向量检索 / Rerank；
- 网络 / CDN / 跨境网络；
- Agent 平台；
- 安全 / 合规；
- 海外云；
- 企业服务与联合方案。

按客户阶段拆：
- Seed / 0→1；
- PMF / A轮；
- Scale / B轮+；
- 成熟企业。

输出：
- 机会强度；
- 采购角色；
- 触发事件；
- 典型销售价值主张；
- 主要竞争/替代方案。
