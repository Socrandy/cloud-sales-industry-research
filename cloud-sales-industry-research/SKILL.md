# 新赛道深度研究报告

## 目标

当用户面对完全陌生的新行业、新赛道、新兴市场、新商业模式或新技术产业时，使用本技能快速建立“高管交流级”行业认知。

最终结果必须帮助用户同时完成三件事：

1. **认知压缩**：快速建立行业全景地图，知道行业为什么存在、如何运转、谁在竞争、钱从哪里来。
2. **形成判断**：不止罗列事实，要解释机制、关键变量、边界条件、争议与未来情景。
3. **转化行动**：明确云计算、AI、数据、算力、模型、Agent 等销售机会，并给出可直接用于 CEO/CTO 沟通的问题。

## 何时使用

在以下请求中优先使用本技能：

- “帮我研究一下 X 这个新赛道”
- “我对 X 完全不了解，帮我快速进入这个行业”
- “我要见 X 行业客户，先帮我把这个行业吃透”
- “按新赛道深度研究报告研究 X”
- 用户要求对陌生行业做深度研究、行业扫描、产业分析、商业模式研究、技术与市场研究

如果用户明确指定其他研究框架或只要求一个很窄的问题，则按用户当次要求执行，不强行展开完整十八章。

## 工作流

### Step 1：先建立研究边界

明确：
- 研究对象是什么；
- 地域范围（全球 / 中国 / 指定市场）；
- 时间基准；
- 用户更关心技术、商业、投资还是销售机会；
- 是否需要 HTML / 文档等交付。

如果用户已经给出这些信息，不重复追问。

### Step 2：进行最新公开信息研究

对于可能变化的内容，必须联网核验，包括：
- 市场玩家；
- 融资；
- 收入 / ARR；
- 产品价格；
- 客户；
- 政策与监管；
- 产品与技术进展；
- 行业事件；
- 市场规模。

优先级：
1. 官方文档 / 政府 / 标准组织；
2. 学术论文；
3. 公司公告 / 投资机构；
4. 权威媒体；
5. 高质量行业研究；
6. 其他二手材料。

不要把营销软文、排行榜、不可追溯的市场规模预测当作核心证据。

### Step 3：先写“一页 Executive Map”

在长报告前先给出一页行业全景，包括：
- 一句话定义；
- 行业存在的第一性原理；
- 当前所处阶段；
- 主要价值链；
- 核心玩家分组；
- 商业化成熟度；
- 关键技术栈；
- 最大利润池；
- 最值得关注的 3–5 个趋势；
- 对云 / AI 销售最重要的机会。

### Step 4：按“五层十八章”展开

必须参考 `references/five-layer-eighteen-chapters.md`。

### Step 5：做高管交流 Cheat Sheet

必须参考 `references/executive-cheatsheet.md`。

### Step 6：做证据分级和判断校验

必须区分：
- **事实**：可由可靠来源直接支持；
- **公司自报**：ARR、客户数、效果等来自公司自身披露；
- **行业观点**：行业人士或机构的解释；
- **推断**：基于事实和机制得出的判断；
- **建议**：针对用户角色的行动建议。

趋势判断必须说明：
- 核心驱动变量；
- 边界条件；
- 可能的反例；
- Bull / Base / Bear 三情景；
- 哪些信号会导致情景切换。

### Step 7：从“行业研究”转成“销售作战地图”

对每个行业都回答：
- 哪些工作负载会消耗云和 AI 资源？
- 哪些成本项可以转化为云采购？
- 哪个客户阶段最容易采购？
- 谁是 User / Decision Maker / Economic Buyer / Influencer / Blocker？
- CEO、CTO、业务负责人分别关心哪些 KPI？
- 哪些事件会触发采购？
- 云厂商真正应该卖“资源”，还是“架构 / 成本 / 全球化 / 数据 / Agent / 联合方案”？

## 中文表达规范

- 报告以中文为主。
- 行业内常见且约定俗成的英文或缩写可直接使用，例如：GEO、SEO、Agent、LLM、GPU、API、SaaS、ARR、CRM。
- 不常见的英文术语优先写中文；必要时首次写“中文（English）”，后文使用中文。
- 标题、表格、流程图也优先中文化，避免英文密度过高。
- 不为了显得专业而堆砌英文术语。

## 推理规范

- 优先从第一性原理解释行业，不把类比当作因果证明。
- 类比只用于帮助理解，并明确适用边界。
- 不把融资额等同于商业成功。
- 不把公司自报案例等同于因果证明。
- 不把“市场很大”当作行业有价值的充分条件。
- 不只列玩家名单，必须进行战略分组。
- 不只讲“趋势”，必须解释驱动机制与关键变量。
- 不只讲“云机会”，必须说明为什么客户会买、谁会买、何时买。

## 输出标准

默认深度报告至少应包含：

1. 一页 Executive Map
2. 五层十八章完整研究
3. 高管交流 Cheat Sheet
4. 云 / AI 销售机会地图
5. 核心术语表（复杂行业建议提供）
6. 研究来源与证据等级
7. 明确的最终行业判断

如用户指定 HTML：
- 使用适合长文阅读的布局；
- 左侧固定目录；
- 正文区域足够宽；
- 适当使用表格、流程图和高亮卡片；
- 不用装饰性设计压缩正文；
- 保留来源与证据说明。

## 成功标准

用户读完后应能做到：
- 用 1–2 分钟向别人解释该行业；
- 理解行业为什么现在发生；
- 说出主要玩家为什么是不同战略组；
- 判断哪个环节最赚钱、哪个环节最脆弱；
- 理解核心技术链路但不必成为工程师；
- 对未来提出 2–3 个有逻辑、有边界条件的判断；
- 与 CEO / CTO 交流时能提出不显外行的问题；
- 明确云计算和 AI 的潜在销售机会。
